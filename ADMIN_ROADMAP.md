# Admin Roadmap — MacvBet

Полный план админ-панели казино MacvBet. Текущая страница `/system/console`
показывает только агрегированную статистику в режиме read-only — этот
документ описывает все механики управления, которые нужно добавить
поверх неё. Цель — чтобы админ управлял казино полностью: пользователи,
игры, RTP, балансы, бонусы, выплаты, безопасность, аудит.

---

## 0. Общие принципы

### Архитектура

- **Все админ-операции идут через `/api/_x/*`** на бэкенде.
- Каждый эндпоинт защищён `adminOnly` middleware (404 для не-админов).
- Каждое мутирующее действие пишется в `admin_audit_log` (новая таблица):
  `id, adminUserId, adminTelegramId, action, targetType, targetId,
  payloadBefore, payloadAfter, ipAddress, createdAt`. Лог нельзя
  удалить из UI — только смотреть.
- Все суммовые операции идут через `bettingPipeline` (атомарный SQL),
  никогда напрямую `UPDATE balance`.
- Двухступенчатое подтверждение для разрушительных действий: админ
  жмёт кнопку → бэкенд возвращает `confirmationToken` со сроком 30 сек
  → админ повторяет запрос с токеном.

### Многоуровневые роли

Расширить `ADMIN_TELEGRAM_IDS` до полноценной таблицы `admin_roles`:

| Роль        | Права |
|-------------|-------|
| `viewer`    | Только смотреть статистику. |
| `support`   | + изменять баланс игрока, открывать диспуты. |
| `manager`   | + менять RTP, конфиги игр, выдавать бонусы. |
| `owner`     | + назначать админов, менять кошелёк казино, видеть аудит. |

В `.env` остаётся `ADMIN_TELEGRAM_IDS` — это `owner`-список, базовый
seed. Owner'ы потом назначают остальных через UI.

### UI

- Левый сайдбар-навигация на десктопе, табы внизу на мобиле.
- Каждый раздел — отдельная страница `/system/console/<section>`.
- Диаграммы: lightweight inline SVG (как сейчас), без chart-библиотек.
- Все таблицы поддерживают поиск, сортировку, пагинацию (50 строк).
- Каждое действие, требующее подтверждения, открывает modal с резюме
  изменений и кнопкой «Подтвердить» в стиле бренда.

## 1. Dashboard `/system/console` (есть, доработать)

**Текущее состояние:** KPI, GGR-таймлайн, per-game, топ-10, биггест-вин.

**Доработать:**

- KPI «ARPU» — средний оборот на игрока за период.
- Карта сессий: live-таблица «кто сейчас на каком экране», обновляется
  по WS из `useNavStore` (нужен серверный хук).
- График ставок по часам — heatmap 24×7 для понимания пиковых нагрузок.

## 2. Управление игроками `/system/console/users`

### Список игроков

**Колонки:** аватарка · имя · @username · TG ID · регистрация · последний
вход · баланс · оборот · GGR · флаги (VIP / banned / locked).

**Фильтры:**
- Поиск по имени, username, TG ID.
- Период регистрации.
- Диапазон баланса.
- Только VIP / banned / inactive 30+ дней.
- Минимальный оборот (для cohort-анализа).

**Сортировка:** по балансу, обороту, GGR, дате регистрации.

### Карточка игрока `/system/console/users/[id]`

#### Профиль
- Аватар, имя, username, TG ID, язык, премиум-статус, IP последнего
  входа, user-agent, страна по IP.
- Дата регистрации, кол-во сессий.
- Реферер (кто его привёл) — кликабельная ссылка на профиль реферера.
- Список рефералов этого игрока.

#### Финансы
- Текущий баланс с возможностью **редактировать** (manager+):
  - Поля «Сумма», «Тип операции» (кредит / дебет / коррекция),
    «Причина» (обязательно текстом, идёт в audit).
  - Превью «Баланс ДО → ПОСЛЕ».
  - Подтверждение через токен.
- История транзакций — фильтр по типу (bet / win / cashout / deposit /
  withdraw / admin_credit / admin_debit / bonus).
- Активные бонусы и их вейджер.

#### История ставок
- Полная таблица ставок: игра, время, ставка, исход, payout, мульт.
- Возможность открыть отдельную ставку → раскрытие seed'a, проверка
  provably-fair вручную.

#### Действия (right rail)
- 🔒 **Заблокировать** — игрок не может играть и выводить средства.
- ⚠️ **Заморозить вывод** — играть может, выводить нет (для расследований).
- 🛡 **Снять блокировку**.
- 👁 **Шпион-режим** — открыть страницу как этот игрок (read-only,
  спец-сессия с пометкой `viewing as`, никаких действий не пишутся
  на его счёт).
- 🎁 **Выдать бонус** — выбор бонуса из каталога, сумма, вейджер.
- 💸 **Принудительный вывод** — owner-only, для возврата средств.
- 🗑 **Удалить аккаунт** — soft-delete, не физическое удаление; все
  ставки сохраняются, GDPR-compliance.

#### Лог действий админов
В нижней части — все действия, которые админы совершали с этим игроком.

### Массовые операции

- Экспорт CSV отфильтрованного списка.
- Bulk-бонус (выдать 100 ₽ всем, кто пришёл за 24h, например).
- Bulk-сообщение (отправить через бота).

## 3. Управление играми `/system/console/games`

### Общий конфиг каждой игры

**Crash / MacvJet:**
- Min/max bet (sliders).
- House edge (%) — текущий 1%.
- Min/max crash multiplier (для теста).
- Length of waiting phase (s).
- Length of starting countdown (s).
- Hash chain seed rotation interval.
- Flag «Pause game» — мгновенно останавливает раунды.

**Mines:**
- Min/max bet.
- House edge per mines tier (default 1%).
- Allowed mines counts (по умолчанию 1–24).
- Max payout cap (anti-jackpot guard).

**Plinko:**
- Min/max bet.
- House edge per risk tier (low / medium / high).
- Multiplier table per risk — табличный редактор: 17 ячеек, каждую
  можно править. Validator: сумма (multiplier × probability) ≤ 1 - edge.
- Max payout cap.

**Coinflip:**
- Min/max bet.
- Step multiplier (текущий 1.94 → 2× минус 3% edge).
- Max rounds (текущий 20).

### Изменение RTP в реальном времени

UI:
1. Слайдер «House edge» 0% — 50% (default 1%).
2. Превью: «При оборотах 1М ₽ ваш ожидаемый GGR = X ₽».
3. График симуляции 10к раундов с этим RTP (Monte Carlo, 100мс).
4. Кнопка «Применить» — изменяет конфиг в Redis, новые раунды
   считаются по новому. **Уже идущие раунды не затрагиваются** (RTP
   фиксируется на момент `processBet`).

### Технически

- Все конфиги хранить в Redis hash `game_config:<gameType>`.
- Engine читает через `gameConfig.get('crash')` с TTL-кэшем 5 сек.
- Изменение пишется в Postgres `game_config_history` для отката.
- API: `GET /api/_x/games/:type`, `PATCH /api/_x/games/:type`.

### Аналитика по игре

Per-game вкладка: количество ставок, оборот, GGR, RTP, средняя ставка,
максимальный мульт, гистограмма мультипликаторов, топ-10 выигрышей.

## 4. Управление балансами и платежами `/system/console/finance`

### Общий обзор

- Total liability (сейчас в Dashboard).
- На бирже / в hot wallet / в cold wallet (разделить, когда будут
  реальные кошельки).
- Net daily P/L график.
- График депозитов и выводов.

### Депозиты `/system/console/finance/deposits`

Таблица всех депозитов: игрок, сумма, метод, время, статус (pending /
confirmed / failed / refunded), txid.

Действия:
- ✅ Подтвердить вручную (если автоматика не сработала).
- ↩ Откатить.
- 🔍 Открыть транзакцию во внешнем эксплорере.

### Выводы `/system/console/finance/withdrawals`

Таблица заявок на вывод. Pending выводы — дефолтный фильтр.

Колонки: игрок · сумма · метод · реквизиты · время заявки · оборот
после депозита (для проверки вейджера) · статус.

Действия:
- ✅ Одобрить → отправить деньги через payment provider, пометить как
  paid, прислать игроку чек ссылкой.
- ❌ Отклонить с указанием причины (текст идёт в TG-уведомление игроку).
- ⚠ В ручную обработку — escalation.

Защита: вывод свыше N ₽ требует двух одобрений (manager + owner).

### Конфиг кошелька

- Адреса крипто-кошельков (USDT TRC20 / BTC / ETH).
- API-ключи провайдеров (Piastrix, FreeKassa, FK Wallet и т.д.) —
  хранятся в Redis encrypted.
- Лимиты на одну операцию.
- Минимальный оборот для вывода (вейджер).
- Комиссии.

## 5. Бонусы и промо `/system/console/bonuses`

### Каталог бонусов

CRUD: создавать / редактировать / архивировать бонусы.

Поля:
- Название, описание.
- Тип: `welcome / deposit / no-deposit / cashback / freebet / referral`.
- Сумма / процент.
- Условие активации: код, депозит ≥ N, все игроки и т.д.
- Вейджер (x N от суммы бонуса).
- Срок действия.
- Лимит на игрока.
- Лимит общий.
- Игры, в которых бонус «работает» (вклад в вейджер).

### Промокоды

Таблица промокодов с кол-вом активаций, остатком, статистикой.
Генератор «100 одноразовых промокодов на 50 ₽ каждый».

### CPA / GGR-реферальная программа

Уже есть в боте. Перенести управление сюда:
- Список рефереров и их балансов CPA / GGR.
- Ставки CPA (₽ за регистрацию) и процент GGR.
- Выплаты партнёрам.

## 6. Контроль безопасности `/system/console/security`

### Аудит-лог

Таблица всех админ-действий. Фильтры по админу, типу, дате, цели.
Каждая строка раскрывается → diff payloadBefore vs payloadAfter.

### Сессии

Все активные WebSocket / HTTP сессии. Возможность:
- Принудительно завершить сессию.
- Заблокировать IP.

### Подозрительные паттерны

Автоматические алерты:
- Новый аккаунт сделал депозит ≥ X ₽ и сразу запросил вывод.
- Игрок выиграл больше 50× от депозита.
- Несколько аккаунтов с одного IP / устройства.
- Резкие пики ставок.

Каждый алерт → строка в этом разделе с быстрыми действиями.

### Anti-fraud

- Фильтры IP / устройств / стран.
- Список запрещённых стран.
- Минимальный возраст аккаунта для вывода.

- Клавиатуры (главное меню) — drag-n-drop.
- Картинки для отдельных команд.

### Рассылки

- Создать рассылку: текст, картинка, кнопки, целевая аудитория

### Команды бота

Таблица доступных игр в боте: cube / bowl / darts / basket / foot /

- Включить / выключить.
- Min/max bet.
- House edge.

### Поддержка

Таблица заявок в поддержку (от пользователей через бот). Статусы:
open / in-progress / closed. Возможность ответить прямо из админки —
бэкенд отправит сообщение через бота.

## Безопасность реализации

Каждая фаза должна заканчиваться:
1. Все эндпоинты гарантируют 404 для не-админов (тесты).
2. Audit-log пишет каждое мутирующее действие.
3. Деструктивные действия требуют 2-step подтверждение.
4. Sensitive поля (ключи провайдеров, seed'ы) шифруются в Redis.
5. UI никогда не показывает секреты по умолчанию — только по клику
   «Раскрыть» с дополнительным подтверждением.
6. Все суммовые операции идут через `bettingPipeline` для атомарности.
