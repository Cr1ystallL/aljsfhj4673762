# Admin Roadmap — MacvBet

Полный план админ-панели казино MacvBet. Текущая страница `/system/console`
показывает только агрегированную статистику в режиме read-only — этот
документ описывает все механики управления, которые мы добавляем поверх.

**Скоуп:** реализуем только то, что уже есть в мини-аппе или нужно для
оперативного управления им. Бонусы / промокоды / рефералы / турниры /
менеджмент контента не делаем — они сейчас живут в боте, который будет
переделан позже отдельным заходом.

---

## 0. Общие принципы

### Архитектура

- Все админ-операции идут через `/api/_x/*` на бэкенде.
- Каждый эндпоинт защищён `adminOnly` middleware (404 для не-админов).
- Каждое мутирующее действие пишется в `admin_audit_log` (новая таблица):
  `id, adminUserId, adminTelegramId, action, targetType, targetId,
  payloadBefore, payloadAfter, ipAddress, createdAt`. Лог нельзя
  удалить из UI — только смотреть.
- Все суммовые операции идут через `bettingPipeline` (атомарный SQL),
  никогда напрямую `UPDATE balance`.
- Двухступенчатое подтверждение для разрушительных действий: админ
  жмёт кнопку → бэкенд возвращает `confirmationToken` со сроком 30 сек
  → админ повторяет запрос с токеном.

### Многоуровневые роли

Расширяем `ADMIN_TELEGRAM_IDS` до полноценной таблицы `admin_roles`:

| Роль        | Права |
|-------------|-------|
| `viewer`    | Только смотреть статистику. |
| `support`   | + изменять баланс игрока. |
| `manager`   | + менять RTP, конфиги игр. |
| `owner`     | + назначать админов, менять конфиг кошелька, видеть аудит. |

В `.env` остаётся `ADMIN_TELEGRAM_IDS` — это `owner`-список, базовый
seed. Owner'ы потом назначают остальных через UI.

### UI

- Левый сайдбар-навигация на десктопе, табы внизу на мобиле.
- Каждый раздел — отдельная страница `/system/console/<section>`.
- Диаграммы: lightweight inline SVG (как сейчас), без chart-библиотек.
- Все таблицы поддерживают поиск, сортировку, пагинацию (50 строк).
- Каждое действие, требующее подтверждения, открывает modal с резюме
  изменений и кнопкой «Подтвердить» в стиле бренда.

### «?» — подсказки

Везде, где админ может что-то менять или интерпретировать данные,
рядом с заголовком стоит маленькая иконка `?`. По нажатию открывается
модалка-подсказка (не tooltip, а полноценный диалог) с понятным
текстом: что эта механика делает, как она влияет на казино / игроков,
на что стоит смотреть в первую очередь. Все «?» используют один общий
компонент `<HelpButton id="…" />`, который рендерит `<HelpModal />`.

## 2. Управление игроками `/system/console/users`

### Список игроков

**Колонки:** аватарка · имя · @username · TG ID · регистрация · последний
вход · баланс · оборот · GGR · флаги (banned / locked).

**Фильтры:**
- Поиск по имени, username, TG ID.
- Период регистрации.
- Диапазон баланса.
- Только banned / inactive 30+ дней.
- Минимальный оборот (для cohort-анализа).

**Сортировка:** по балансу, обороту, GGR, дате регистрации.

### Карточка игрока `/system/console/users/[id]`

#### Профиль
- Аватар, имя, username, TG ID, язык.
- Дата регистрации, кол-во сессий.
- IP последнего входа, user-agent.

#### Финансы
- Текущий баланс с возможностью **редактировать** (manager+):
  - Поля «Сумма», «Тип операции» (кредит / дебет / коррекция),
    «Причина» (обязательно текстом, идёт в audit).
  - Превью «Баланс ДО → ПОСЛЕ».
  - Подтверждение через токен.
- История транзакций — фильтр по типу (bet / win / cashout / deposit /
  withdraw / admin_credit / admin_debit).

#### История ставок
- Полная таблица ставок: игра, время, ставка, исход, payout, мульт.
- Возможность открыть отдельную ставку → раскрытие seed'a, проверка
  provably-fair вручную.

#### Действия (right rail)
- 🔒 **Заблокировать** — игрок не может играть и выводить средства.
- ⚠️ **Заморозить вывод** — играть может, выводить нет (для расследований).
- 🛡 **Снять блокировку**.
- 👁 **Шпион-режим** — открыть страницу как этот игрок (read-only,
  спец-сессия с пометкой `viewing as`).
- 💸 **Принудительный вывод** — owner-only, для возврата средств.
- 🗑 **Удалить аккаунт** — soft-delete, не физическое удаление; все
  ставки сохраняются, GDPR-compliance.

`?` рядом с каждым действием объясняет последствия.

#### Лог действий админов
В нижней части — все действия, которые админы совершали с этим игроком.

### Массовые операции

- Экспорт CSV отфильтрованного списка.
- Bulk-сообщение через бота.

## 3. Управление играми `/system/console/games`

Каждое поле в этом разделе сопровождается кнопкой `?` рядом — модалка
объясняет понятным языком, что эта настройка делает, как она влияет
на RTP / поведение игры / финансы казино.

### Общий конфиг каждой игры

**MacvJet (Crash):**
- Min/max bet (sliders) — `?` лимиты на одну ставку.
- House edge (%) — текущий 1%. `?` объясняет что это процент, который
  казино удерживает в долгосроке от каждой ставки.
- Min/max crash multiplier (для теста) — `?` искусственное ограничение
  диапазона crash для тестов / турниров.
- Length of waiting phase (s) — `?` время приёма ставок между раундами.
- Length of starting countdown (s) — `?` сколько идёт обратный отсчёт
  перед взлётом.
- Hash chain seed rotation interval — `?` как часто меняется
  серверный seed для provably-fair.
- Flag «Pause game» — мгновенно останавливает раунды. `?` объясняет
  что текущие ставки доигрываются, новые приниматься не будут.

**Mines:**
- Min/max bet — `?`.
- House edge per mines tier (default 1%) — `?` отдельный edge для
  каждого количества мин.
- Allowed mines counts (по умолчанию 1–24) — `?` какие значения мин
  разрешены игроку.
- Max payout cap — `?` верхний лимит выплаты за один раунд (anti-jackpot).

**Plinko:**
- Min/max bet — `?`.
- House edge per risk tier (low / medium / high) — `?`.
- Multiplier table per risk — табличный редактор: 17 ячеек, каждую
  можно править. Validator: сумма (multiplier × probability) ≤ 1 - edge.
  `?` подсказка с формулой и примером.
- Max payout cap — `?`.

**Coinflip:**
- Min/max bet — `?`.
- Step multiplier (текущий 1.94 → 2× минус 3% edge) — `?`.
- Max rounds (текущий 20) — `?` ограничение длины серии в режиме
  «С умножением».

### Изменение RTP в реальном времени

UI:
1. Слайдер «House edge» 0% — 50% (default 1%).
2. Превью: «При оборотах 1М ⌭ ваш ожидаемый GGR = X ⌭».
3. График симуляции 10к раундов с этим RTP (Monte Carlo, 100мс).
4. Кнопка «Применить» — изменяет конфиг в Redis, новые раунды
   считаются по новому. **Уже идущие раунды не затрагиваются** (RTP
   фиксируется на момент `processBet`).
5. `?` рядом со слайдером — объяснение, что такое RTP, как edge
   соотносится с RTP (RTP = 100% - edge), и почему 1% — индустриальный
   стандарт.

### Технически

- Все конфиги хранить в Redis hash `game_config:<gameType>`.
- Engine читает через `gameConfig.get('crash')` с TTL-кэшем 5 сек.
- Изменение пишется в Postgres `game_config_history` для отката.
- API: `GET /api/_x/games/:type`, `PATCH /api/_x/games/:type`.

### Аналитика по игре

Per-game вкладка: количество ставок, оборот, GGR, RTP, средняя ставка,
максимальный мульт, гистограмма мультипликаторов, топ-10 выигрышей.

## 4. Управление балансами и платежами `/system/console/finance`

### Общий обзор

- Total liability (сейчас в Dashboard). `?` объясняет что это сумма
  всех денег на счетах игроков — потенциальные обязательства казино.
- На бирже / в hot wallet / в cold wallet (разделить, когда будут
  реальные кошельки). `?` объясняет три уровня хранения средств,
  какой для чего нужен.
- Net daily P/L график. `?` объясняет как считается дневной P/L
  (deposits + bets - withdrawals - payouts).
- График депозитов и выводов. `?` объясняет что показывает каждая
  кривая и как читать соотношение.

### Депозиты `/system/console/finance/deposits`

Таблица всех депозитов: игрок, сумма, метод, время, статус (pending /
confirmed / failed / refunded), txid.

Действия:
- ✅ Подтвердить вручную (если автоматика не сработала).
- ↩ Откатить.
- 🔍 Открыть транзакцию во внешнем эксплорере.

`?` для каждого статуса объясняет что он означает.

### Выводы `/system/console/finance/withdrawals`

Таблица заявок на вывод. Pending выводы — дефолтный фильтр.

Колонки: игрок · сумма · метод · реквизиты · время заявки · оборот
после депозита (для проверки вейджера) · статус.

Действия:
- ✅ Одобрить → отправить деньги через payment provider, пометить как
  paid, прислать игроку чек ссылкой.
- ❌ Отклонить с указанием причины (текст идёт в TG-уведомление игроку).
- ⚠ В ручную обработку — escalation.

Защита: вывод свыше N ⌭ требует двух одобрений (manager + owner). `?`
объясняет логику двойного подтверждения.

### Конфиг кошелька

Каждое поле сопровождается кнопкой `?` с объяснением.

- Адреса крипто-кошельков (USDT TRC20 / BTC / ETH) — `?` куда поступают
  крипто-депозиты, как менять адрес безопасно.
- API-ключи провайдеров (Piastrix, FreeKassa, FK Wallet и т.д.) —
  хранятся в Redis encrypted. `?` зачем нужны эти провайдеры, что
  будет если ключ скомпрометирован.
- Лимиты на одну операцию — `?` как лимиты защищают от фрода.
- Минимальный оборот для вывода (вейджер) — `?` зачем нужен вейджер,
  как считается.
- Комиссии — `?` как комиссии распределяются между провайдером и
  казино.

## 5. Контроль безопасности `/system/console/security`

### Аудит-лог

Таблица всех админ-действий. Фильтры по админу, типу, дате, цели.
Каждая строка раскрывается → diff payloadBefore vs payloadAfter.
`?` рядом с заголовком объясняет назначение журнала.

### Сессии

Все активные WebSocket / HTTP сессии. Возможность:
- Принудительно завершить сессию.
- Заблокировать IP.

### Подозрительные паттерны

Автоматические алерты:
- Новый аккаунт сделал депозит ≥ X ⌭ и сразу запросил вывод.
- Игрок выиграл больше 50× от депозита.
- Несколько аккаунтов с одного IP / устройства.
- Резкие пики ставок.

Каждый алерт → строка в этом разделе с быстрыми действиями. `?` для
каждого типа алерта объясняет почему этот паттерн подозрителен.

### Anti-fraud

- Фильтры IP / устройств / стран.
- Список запрещённых стран.
- Минимальный возраст аккаунта для вывода.

## 6. Бот: рассылки `/system/console/broadcasts`

Только рассылки. Остальные функции бота (команды, поддержка, конфиг

- Inline-кнопки (опционально, до 3-х).

После отправки — таблица результатов: всего, доставлено, заблокировали,
открыли (если есть метка), кликов на каждую кнопку.

`?` рядом с каждым полем объясняет назначение.

## Безопасность реализации

Каждая фаза должна заканчиваться:
1. Все эндпоинты гарантируют 404 для не-админов (тесты).
2. Audit-log пишет каждое мутирующее действие.
3. Деструктивные действия требуют 2-step подтверждение.
4. Sensitive поля (ключи провайдеров, seed'ы) шифруются в Redis.
5. UI никогда не показывает секреты по умолчанию — только по клику
   «Раскрыть» с дополнительным подтверждением.
6. Все суммовые операции идут через `bettingPipeline` для атомарности.

## Прогресс реализации

Раздел будет обновляться после каждой фазы.

### ✅ Реализовано

**Базовая инфраструктура:**
- **Dashboard** (read-only): KPI с `?` подсказками (Игроки, Обязательства,
  Оборот, GGR/RTP), 14-дневный SVG-таймлайн GGR с подсказкой, per-game
  таблица, топ-10 игроков (кликабельные), крупнейший выигрыш.
- **Скрытие админ-поверхности**: все эндпоинты `/api/_x/*` отдают 404
  для не-админов; кнопка «Админ» в профиле появляется только после
  silent-probe; страница `/system/console/*` рендерит 404 для
  неавторизованных.
- **Назначение owner'ов через ENV**: `ADMIN_TELEGRAM_IDS` в `.env`
  бэкенда (comma-separated TG ID).
- **Общий компонент `<HelpButton />`** + `<HelpModal />` с подробными
  пояснениями каждого механизма.
- **Левая навигация (`<AdminShell />`)** между всеми разделами админки.

**Фаза 1 — Базовое управление:**
- **Audit-log** (`admin_audit_log` таблица): записывается каждое
  мутирующее действие с before/after снимками, причиной, IP. Вьюер
  `/system/console/audit` с фильтрами и пагинацией.
- **Список игроков** `/system/console/users` с поиском по имени /
  username / TG ID и фильтром `Заблокированные / С блоком вывода`.
  Серверная пагинация по 50.
- **Карточка игрока** `/system/console/users/[id]` с профилем,
  балансом, статистикой, последними 30 ставками, последними 30
  транзакциями, журналом действий админов по этому игроку.
- **Корректировка баланса** (`POST /api/_x/users/:id/balance`):
  атомарная транзакция с обязательной причиной; защита от
  непреднамеренного ухода в минус (требует слово «clawback» в
  причине); запись в журнал.
- **Блокировка игрока** (`isBlocked`) — полный запрет на ставки,
  проверяется в `bettingPipeline.processBet`.
- **Заморозка вывода** (`withdrawalLocked`) — флаг для будущей
  pipeline вывода (Фаза 4).
- **Список выводов** `/system/console/withdrawals` (read-only).

**Фаза 2 — Игры и RTP:**
- **Конфиг каждой игры** (`/system/console/games`):
  - Пауза игры — мгновенная заморозка приёма ставок без рестарта.
  - Min/Max bet — лимиты на одну ставку.
  - House edge / RTP — слайдер 0-50%, превью RTP.
  - Crash: длина окна ставок, обратный отсчёт.
  - Mines: мин/макс мин, лимит выплаты.
  - Plinko: лимит выплаты.
  - Coinflip: шаг множителя, макс. раундов.
- **Хранение** — Redis hash `game_config:<gameType>`, движок читает с
  TTL 5с. Все engine'ы проходят через `bettingPipeline.processBet`,
  который сверяет ставку с актуальным конфигом и блокирует если игра
  на паузе.
- **`?` подсказки** — на каждое поле, объясняют что делает и когда
  применять.
- Каждое сохранение требует причину и пишется в аудит.

**Фаза 3 — Безопасность:**
- **Anti-fraud алерты** (`/system/console/alerts`):
  - `huge_win` — выигрыш игрока ≥ ×10 от его последнего депозита.
    Severity: ×100+ → critical, ×30+ → warn, ×10+ → info.
  - `rapid_bets` — > 200 ставок за последний час с одного аккаунта.
  - Список обновляется автоматически каждые 30 секунд, клик по алерту
    открывает карточку игрока.
- **Активные сессии** (`/system/console/sessions`):
  - Список всех живых JWT-сессий из Redis. Имя/Telegram ID/IP/время
    последней активности.
  - Кнопка «Отозвать» с обязательной причиной → запись в аудит.
  - Автообновление каждые 15 секунд.
- **Назначение админов** (`/system/console/admins`):
  - Seed-админы из `.env` (untouchable from UI) и dynamic-админы
    (хранятся в Redis `admins:dynamic`, добавляются/снимаются из UI).
  - Добавление по Telegram ID + причина → audit.
  - `adminOnly` middleware теперь проверяет и env, и Redis-cache (TTL 5с).

**Фаза 4 — Финансы и кошелёк:**
- **Заявки на вывод** (`/system/console/withdrawals`):
  - Таблица `withdrawal_requests` с lifecycle pending → approved /
    rejected → paid.
  - Кнопки «Одобрить» / «Отклонить» с обязательной причиной.
  - Отклонение возвращает деньги на баланс через атомарную SQL-транзакцию.
  - Фильтры «Ожидают» / «Все».
- **Депозиты** (`/system/console/deposits`):
  - Read-only список транзакций типа `deposit`.
  - Клик → карточка игрока.
- **Конфиг кошелька** (`/system/console/wallet`):
  - Крипто-адреса (USDT TRC20, BTC, ETH).
  - API-ключи провайдеров (Piastrix, FreeKassa, FK Wallet) с маской
    `••••XXXX` по умолчанию + кнопка «Раскрыть» (записывается в аудит).
  - Лимиты на депозит / вывод.
  - Множитель оборота (вейджер).
  - Комиссии (крипто, карта).
  - Все секреты в аудите маскируются перед записью.

### 🟡 Частично
- **Назначение админов** — реализовано (seed + dynamic), но пока без
  ролей (viewer / support / manager / owner). Все админы с одинаковыми
  правами.
- **Платёжные провайдеры** — конфиг ключей и кошельков есть, но сами
  интеграции (Piastrix, FreeKassa, CryptoPay) не подключены — депозиты
  и одобренные выводы пока работают только как ledger-записи без
  реальной отправки денег.
