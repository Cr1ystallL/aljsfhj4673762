# Доступ к VPS

Продакшен проекта живёт на удалённом Linux-VPS (`163.5.41.97`, каталог `/var/www/MACVBET/mini-app`,
процессы под PM2: `macvbet-backend`, `macvbet-frontend`, `macvbet-bot`). Полное описание окружения —
в `SERVER_INFO.md`.

## Шаг 1. Определи, есть ли прямой доступ

```bash
./scripts/agent_vps.sh check
```

- **Команда отработала** — прямой SSH есть, работай по разделу «Прямой доступ».
- **Команда сказала, что не задан `VPS_HOST` / `VPS_USER` / `VPS_SSH_KEY`** — доступа нет,
  переходи к разделу «Запасной режим». Не пытайся угадывать пароли и не запускай `ssh` вручную.

## Шаг 2а. Прямой доступ

Все обращения к серверу — только через `./scripts/agent_vps.sh`, он сам поднимает ключ из секретов
и фиксирует ключ хоста.

```bash
./scripts/agent_vps.sh run 'pm2 status'
./scripts/agent_vps.sh logs macvbet-backend 200
./scripts/agent_vps.sh run 'cd /var/www/MACVBET/mini-app && git log --oneline -5'
./scripts/agent_vps.sh pull-file /var/www/MACVBET/mini-app/.env.example /tmp/env.example
```

Правила при прямом доступе:

- **Читать можно свободно, писать — осознанно.** Логи, `git log`, `pm2 status`, `df -h`,
  `SELECT`-запросы — без спроса. Всё, что меняет состояние прода, требует явного согласия
  пользователя в текущей задаче.
- **Никогда без явной просьбы:** `rm -rf`, `DROP`/`DELETE`/`UPDATE` в боевой БД, правка балансов
  пользователей, `pm2 delete`, изменение правил `ufw`, ротация ключей и токенов.
- **Перед сборкой помни про OOM.** `pnpm build` на этом сервере уже ронял SSH-сессию по нехватке
  памяти. Не запускай сборку в фоне вслепую — следи за выводом.
- **Перед `pnpm build` всегда `npx prisma generate`** в `apps/backend`, иначе бэкенд упадёт с
  `Cannot find module '.prisma/client/default'`.
- **Не понижай версию Next.js ниже 15.5.x** — на 15.0.0 сервер словил RCE и майнер.
- **Секреты не печатай.** Не выводи `.env`, содержимое `BOT_TOKEN`, `CRYPTOPAY_TOKEN`,
  `DATABASE_URL` ни в ответ, ни в логи, ни в коммиты.
- **Деплой — только из смёрдженного кода.** Сначала PR и мердж, потом `git pull` на сервере.

Типовой деплой:

```bash
./scripts/agent_vps.sh run 'set -e
  cd /var/www/MACVBET/mini-app
  git pull
  pnpm install
  cd apps/backend && npx prisma generate && cd ../..
  pnpm build
  pm2 restart all
  pm2 save'
```

## Шаг 2б. Запасной режим (доступа нет)

Это поведение по умолчанию, оно описано в `AI_RULES.md` и `.agents/AGENTS.md`. Команды выполняет
пользователь руками, агент их только готовит:

- Собери **все** серверные команды в **один** markdown-блок ` ```bash ` в самом конце ответа.
- Первой строкой всегда `clear`.
- Внутри блока — комментарии `#`, объясняющие каждый шаг.
- Там, где это спасает от проблем с `PATH`, используй полные пути (`/usr/sbin/ufw`).
- Не разбивай на несколько блоков: смысл в том, чтобы пользователь нажал «Копировать» один раз.

## Как включить прямой доступ

Нужны секреты `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY` (base64), опционально `VPS_PORT` и
`VPS_HOST_KEY`. Пошаговая инструкция с генерацией ключа и ограничением прав — в
`docs/VPS_AGENT_ACCESS.md`. Если пользователь просит «дай агенту доступ к серверу», отправляй его
туда.
